# Settings are grouped by glossary term, one level deep

The config file nests each setting in an object named after the glossary term it acts on, such as `pane.scrollBar` or `commandPalette.nesting`, and nests no deeper. A setting that is the term's whole choice, such as which Theme, which Shell program, whether the Session Banner shows or which Menu Bar Icon, goes by the term's name as a plain value, such as `"theme": "Dracula"`, rather than a one-key object. A setting for one property of a term keeps its own name inside the term's group even when it is the term's only setting, such as `tab.startDirectory`, so it reads as that property and matches `pane.startDirectory`. A setting no term covers gets a new glossary term first, as Login Launch, Background and Menu Bar Icon did, rather than a catch-all group. `keyBindings` stays one block, since its action names already carry their terms. Grouping by term keeps the settings in the words the app shows the user; the glossary's sections (Layout, Navigation, Appearance) were rejected as a second vocabulary to learn, and dotted flat keys such as `"pane.scrollBar"` as a hierarchy in names alone. A plain-value term that later gains a second setting changes shape from a plain value to an object, which breaks config files that set it.
